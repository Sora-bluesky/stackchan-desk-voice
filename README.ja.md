# stackchan-desk-voice

M5Stack の StackChan（CoreS3）を、PC 用の USB マイク兼スピーカーにする非公式のファンメイドファームウェアです。画面には雲の形の顔が動きます。頭を2回タップすると、PC のデスクトップ AI チャットアプリで音声通話を始めたり終えたりできます。

M5Stack やｽﾀｯｸﾁｬﾝの公式プロジェクトではありません。詳しくは[免責](#免責)をご覧ください。

| 頭をダブルタップすると通話が始まり、目が変わる | 先に目が動き、あとから首が向く |
|---|---|
| ![頭のダブルタップで通話開始](docs/images/double-tap-call.gif) | ![目が先、首があと](docs/images/eyes-lead-head.gif) |

## できること

- PC からは USB Audio Class 2 のマイクとスピーカーに見えます。形式は 48 kHz・16 bit・モノラルです。
- 頭のセンサーを2回タップすると、USB キーボードとしてキーを1つ送ります（既定は F13）。このキーを PC 側のスクリプトが受け取り、アプリの音声ボタンをクリックします。
- 通話中は PC 側のスクリプトが Scroll Lock のランプを点けます。通話中かどうかはアプリのウィンドウを見て判断するので、ウィンドウは最小化せずに開いておいてください。最小化すると「通話していない」と判断されます。ファームウェアはこのランプの状態を読んで顔を切り替えるので、アプリ側で通話を終えても本体の表示が追いつきます。通話が終わると短い音が鳴ります。
- 顔はコードで描いています。青い雲に白いカプセル形の目が2つです。待機、まばたき、聞いている（マイクに声が入っている）、考えている（話し終えた直後）、話している（PC から音が出ている）、なでられた（頭をなでる）、眠い（3分間なにも起きない）、寝ている（10分）を切り替えます。
- 画面に触れると、目が指を追います。指を離しても1秒ほどそちらを見ています。
- 待機中は20〜30秒ごとに首のサーボで向きを変えます。先に目が動き、首があとから付いていきます。誰かが話し始めるとすぐ止まります。
- 待機中の首振りでは、サーボが動く少し前から止まった少しあとまでマイクが無音を送るので、モーター音が通話に乗りません。USB の音声ストリームは止めません。起動時に首の位置を保つ動きと、手で首を動かしたあとに位置を保ち直す動きでは、無音にしません。
- 首を手で押すとサーボが力を抜き、離したあとはその位置で止まります。
- 直近のログ数行と状態の行を画面に重ねて出せます。画面の右上を3秒長押しすると表示を切り替えます。
- 前回のリセットが電圧低下（ブラウンアウト）だった場合は、音量の上限を50%にし、サーボを止めて起動します。

## 必要なもの

- M5Stack 製の StackChan キット（CoreS3 ベース。ESP32-S3、フラッシュ 16 MB、PSRAM 8 MB）
- データ通信ができる USB-C ケーブル（充電専用のものは使えません）
- Windows の PC
- ビルド用の ESP-IDF v5.4.2
- PC 側スクリプト用の [AutoHotkey v2](https://www.autohotkey.com/)

## ビルド

```sh
idf.py set-target esp32s3
idf.py build
```

`sdkconfig.defaults` は自動で読み込まれます。依存コンポーネントの版は `dependencies.lock` で固定しています。できあがるアプリイメージは `build/stackchan-desk-voice.bin` です。

## 書き込み

書き込む前に、この節を最後まで読んでください。

出荷時のファームウェアは、サーボの原点の較正値など本体ごとのデータを NVS に保存しています。このファームウェアも同じ場所の NVS を使い、その較正値を読みます。そのため次の3点を守ってください。

- 最初にフラッシュ 16 MB をまるごとバックアップする。
- 書き込むのはアプリイメージだけで、場所は 0x20000 にする。これで NVS には触れません。
- `erase-flash` も、Web 版書き込みツールの「Erase」ボタンも使いません。

### 1. ダウンロードモードに入る

StackChan を PC につなぎ、ダウンロードモードに入れます。このキットでは、リセットボタンを3秒ほど長押しすると新しい COM ポートが現れます。うまくいかない場合は M5Stack のドキュメントで手順を確かめてください。このファームウェアが動いているあいだ USB はオーディオ機器として働くので、esptool の自動リセットでは入れないことがあります。そのときはリセットボタンを使ってください。

### 2. バックアップ

```sh
python -m esptool --chip esp32s3 -p COMx read-flash 0 0x1000000 stackchan-backup-16MB.bin
```

`COMx` は実際のポート名に置き換えます。このファイルは大事に保管してください。2回読み出して中身が一致するか比べておくと安心です。

### 3. パーティションテーブルを確かめる

アプリイメージだけを書き込む方法は、本体にすでにあるパーティションテーブルで、十分な大きさのアプリ用の領域が 0x20000 から始まっていることが前提です。出荷時の StackChan のテーブルは OTA 用の2枠構成で、1枠目の `ota_0` が 0x20000 から 5056K（0x4f0000）あります。本体から読み出すか、バックアップの同じ範囲を切り出して確かめてください。

```sh
python -m esptool --chip esp32s3 -p COMx read-flash 0x8000 0xc00 ptable.bin
python $IDF_PATH/components/partition_table/gen_esp32part.py ptable.bin
```

`ota_0,app,ota_0,0x20000,5056K` のような行が出るはずです。0x20000 から始まるアプリ用の領域が無ければ、アプリイメージだけの書き込みはしないでください。

どの枠を起動するかは `otadata` に記録されていて、ブートローダーはそれに従います。開発に使った本体では `ota_0` が起動しました。手順 4 のあとも出荷時のファームウェアが起動する場合は、別の枠から起動しています。バックアップを書き戻して、そこで止めてください。

### 4. アプリイメージを書き込む

```sh
python -m esptool --chip esp32s3 -p COMx write-flash 0x20000 build/stackchan-desk-voice.bin
```

書き込んだらリセットボタンを押すか、電源を入れ直すと起動します。

コマンドは esptool v5 の書き方です。v4 では `read_flash` と `write_flash` になります。

### 元に戻す

ダウンロードモードに入り、バックアップをアドレス 0 に書き戻します。

```sh
python -m esptool --chip esp32s3 -p COMx write-flash 0 stackchan-backup-16MB.bin
```

## PC 側の準備

1. StackChan を USB でつなぎます。Windows のサウンド設定かアプリの音声設定で、マイクとスピーカーの両方に **StackChan** を選びます。
2. AutoHotkey v2 を入れて `pc/voice-toggle.ahk` を起動します。タスクトレイに常駐します。
3. `pc/voice-toggle.ini` を作り、対象アプリの実行ファイル名を書きます。

   ```ini
   [target]
   exe=YourApp.exe
   ```

   `exe` を書かなかった場合は、スクリプト冒頭の `DefaultExe` の値を使います。
4. アプリを開きます。StackChan の頭をダブルタップするか、本体なしで試すなら **Ctrl+Alt+Shift+T** を押します。

スクリプトの動きは次のとおりです。

- F13 を受けると、アプリのウィンドウを前面に出して音声ボタンをクリックします。まず赤い終了ボタンを探し、なければ右下あたりで色と形から開始ボタンを探します。クリックしたあと、マウスは元の位置に戻ります。
- 開始ボタンが見つからないときは、記録しておいた位置をクリックします。位置を記録するには、マウスを音声ボタンの上に置いて **Ctrl+Alt+Shift+G** を押します。位置はウィンドウからの相対座標として ini に保存されます。
- 300 ms ごとに通話中かどうかを調べ、Scroll Lock をそれに合わせます。ファームウェアがこのランプを読むので、アプリ側で通話を始めたり終えたりしても顔が追いつきます。

Windows 版 Grok デスクトップアプリ（xAI）の音声モードで動作を確認しています。ほかのアプリでは、ボタンの見つけ方をそのアプリに合わせる必要があります。

## 設定

`idf.py menuconfig` の「StackChan desk voice firmware」で変えるか、`sdkconfig.defaults` に書き足します。

| 項目 | 既定値 | 内容 |
|---|---|---|
| `CONFIG_STACKCHAN_USB_HID` | y | USB をオーディオと HID キーボードの複合デバイスにする。オフにするとオーディオだけになり、ダブルタップは顔の切り替えだけになる |
| `CONFIG_STACKCHAN_HID_KEYCODE` | 0x68（F13） | ダブルタップで送る HID キーコード |
| `CONFIG_STACKCHAN_HID_MODIFIER` | 0x00 | そのキーの修飾ビット（0x01 左 Ctrl、0x02 左 Shift、0x04 左 Alt） |
| `CONFIG_STACKCHAN_VOLUME_CAP` | 100 | スピーカー音量の上限。コーデック音量に対する % で、10〜100 |
| `CONFIG_STACKCHAN_SPK_BOOST_DB` | 0 | ピークリミッター付きのスピーカー増幅。0〜15 dB。0 なら処理しない |
| `CONFIG_STACKCHAN_MIC_GAIN_DB` | 30 | ES7210 のマイクゲイン。0〜37 dB |
| `CONFIG_STACKCHAN_SERVO` | n（`sdkconfig.defaults` では y） | 首のサーボと待機中の首振り |
| `CONFIG_STACKCHAN_SERVO_LOOK_MIN_S` | 20 | 首振りの間隔の最短（秒） |
| `CONFIG_STACKCHAN_SERVO_LOOK_MAX_S` | 30 | 首振りの間隔の最長（秒） |
| `CONFIG_STACKCHAN_MIC_MUTE_PRE_MS` | 80 | サーボが動く前にマイクを無音にする時間（ms）。目を先に動かすので、動く前には必ず 150 ms 以上待つ。実際の無音は 150 ms 以上になり、150 未満の値は効かない |
| `CONFIG_STACKCHAN_MIC_MUTE_POST_MS` | 200 | サーボが止まったあとマイクを無音にする時間（ms） |
| `CONFIG_STACKCHAN_AEC` | n | 予約のみ。エコーキャンセルは実装していない |
| `CONFIG_STACKCHAN_DEBUG_OVERLAY` | y | 起動時にログを画面に重ねて出す |
| `CONFIG_STACKCHAN_SPK_DBFS_ON` | -45 | スピーカーの音がこの値（dBFS）を超えたら「話している」顔にする |
| `CONFIG_STACKCHAN_VAD_MARGIN_DB` | 12 | マイクの音がノイズの底からこの dB 以上高ければ声とみなす |

## 制限

- エコーキャンセルはありません。`aec_hook` は音をそのまま通すだけの差し込み口です。アプリ側のエコー対策を使うか、音量を控えめにしてください。
- PC 側のスクリプトは Windows でしか動きません。AutoHotkey と Win32 の呼び出しを使っています。
- PC 側のスクリプトは、アプリのウィンドウを見て通話中かどうかを判断します。ウィンドウを最小化すると「通話していない」と判断されるので、開いておいてください。
- スクリプトはボタンを色と形で探すので、アプリの画面が更新されると見つけられなくなることがあります。その場合は位置の記録（Ctrl+Alt+Shift+G）で補えます。
- 顔はｽﾀｯｸﾁｬﾝや M5Stack の公式デザインではなく、このプロジェクト用にコードで描いたものです。
- コードには診断用の安全モード（スピーカーの試験音、マイクの音量メーター、I2C チップの確認）があり、起動中に画面か頭に触れたままにすると入る作りです。ただ、試した範囲ではまだ入れていないので、当てにしないでください。
